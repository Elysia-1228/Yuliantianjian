# 全景统一视图 (Unified Trace View) 部署指南

## 📋 功能概述

本次升级实现了**全景统一溯源视图**，系统能够根据攻击复杂度自动选择展示粒度：

- **简单攻击**（端口扫描、DDoS）→ **基础网络视图**（3个节点）
- **复杂攻击**（SQL注入、Webshell）→ **全景溯源视图**（5-7个节点，包含进程和文件）

## 🎯 架构设计

```
Python NIDS (服务器 A)
    ↓ 检测到攻击
    ↓ 根据攻击类型，添加主机层数据
    ↓ 推送告警到 Java 后端
    
Java 后端 (服务器 B)
    ↓ 接收告警，保存到数据库
    ↓ 前端请求生成图谱
    ↓ 查询数据库，获取 affectedProcess 和 affectedFile
    ↓ 根据是否有主机层数据，动态构建图谱
    
前端 (React)
    ↓ 接收图谱数据
    ↓ 自动识别节点类型 (process/file/server/firewall)
    ↓ 渲染全景溯源视图
```

## 🔧 部署步骤

### 1. 数据库升级

在 MySQL 中执行以下 SQL 脚本：

```bash

```

**脚本内容：**
```sql
-- 添加攻击类型字段
ALTER TABLE potential_threat_alert 
ADD COLUMN attack_type VARCHAR(100) COMMENT '攻击类型' AFTER target_ip;

-- 添加受影响进程字段
ALTER TABLE potential_threat_alert 
ADD COLUMN affected_process VARCHAR(255) COMMENT '受影响的进程名' AFTER attack_type;

-- 添加受影响文件字段
ALTER TABLE potential_threat_alert 
ADD COLUMN affected_file VARCHAR(500) COMMENT '受影响的文件路径' AFTER affected_process;

-- 添加详细消息字段
ALTER TABLE potential_threat_alert 
ADD COLUMN message TEXT COMMENT '详细告警信息' AFTER affected_file;

-- 添加索引（提升查询性能）
CREATE INDEX idx_source_target ON potential_threat_alert(source_ip, target_ip, occur_time);
CREATE INDEX idx_attack_type ON potential_threat_alert(attack_type);
```

## 🚨 常见问题

### Q1: 图谱只显示 3 个节点，没有进程和文件？

**原因：** 数据库中没有 `affectedProcess` 字段的数据。

**解决：**
1. 确认数据库已执行升级脚本
2. 确认 Python NIDS 正在运行
3. 重新发起攻击，查看数据库是否有新记录

### Q2: Java 后端报错 "Unknown column 'affected_process'"

**原因：** 数据库未升级。

**解决：**
```bash
mysql -u root -p < BackCode/sql/upgrade_unified_view.sql
```

### Q3: 前端节点显示为灰色方块

**原因：** 节点类型不匹配。

**解决：** 检查 Java 后端返回的节点 `type` 字段是否正确（应为 `process`、`file`、`server` 等）。
