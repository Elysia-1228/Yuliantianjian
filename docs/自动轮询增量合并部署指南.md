# 自动轮询增量合并部署指南

## 📋 功能概述

本次升级实现了**自动轮询机制 (Auto-Polling)**，解决了手动刷新导致 `currentThreatId` 状态丢失的问题。

### 核心问题
- **旧方案**：用户必须手动按 F5 刷新页面才能看到新数据
- **Bug**：手动刷新会导致 React 状态丢失，`currentThreatId` 被清空
- **后果**：前端认为每次都是新攻击，无法形成完整的攻击链路图

### 新方案
- **自动轮询**：每 2 秒自动拉取最新告警数据
- **状态保持**：不需要刷新页面，React 状态始终保持
- **智能合并**：根据 `threatId` 自动判断是新攻击还是增量更新

## 🎯 工作原理

```
Python NIDS 检测到攻击
    ↓
生成固定的 threatId (基于 src_ip)
    ↓
分多次推送节点数据 (0.1-0.4秒间隔)
    ↓
Java 后端接收并保存到数据库
    ↓
前端每 2 秒自动轮询数据库
    ↓
比对 threatId
    ├─ 不同 → 清空旧图谱，显示新攻击
    └─ 相同 → 增量合并，追加新节点
    ↓
图谱自动"生长"，无需手动刷新
```

## 🔧 核心代码

### 1. 自动轮询机制 (ThreatTracing.tsx)

```typescript
useEffect(() => {
    // 只在 PIDS 视图且已启动分析时才轮询
    if (viewMode !== 'pids' || !pidsStarted) {
        return;
    }

    console.log('[自动轮询] 启动轮询机制，每 2 秒检查新数据');

    const pollInterval = setInterval(async () => {
        try {
            // 从数据库获取最新的告警记录
            const response = await fetch('http://127.0.0.1:8985/api/analysis/alert?pageNum=1&pageSize=1');
            const result = await response.json();
            
            if (result.code === 1 && result.data?.records?.length > 0) {
                const latestAlert = result.data.records[0];
                const incomingThreatId = latestAlert.threatId;
                
                if (!incomingThreatId) return;

                console.log('[自动轮询] 收到新数据，threatId:', incomingThreatId);

                // 判断是新攻击还是增量更新
                if (currentThreatId !== incomingThreatId) {
                    // 新攻击：重置图谱
                    console.log('[自动轮询] 检测到新攻击，重置图谱');
                    setCurrentThreatId(incomingThreatId);
                    
                    // 调用后端生成图谱
                    const graphResponse = await fetch('http://127.0.0.1:8985/api/tracing/result/generate-graph', {
                        method: 'POST',
                        headers: { 'Content-Type': 'application/json' },
                        body: JSON.stringify({
                            source_ip: latestAlert.sourceIp,
                            target_ip: latestAlert.targetIp,
                            attack_type: latestAlert.attackType
                        })
                    });
                    
                    const graphResult = await graphResponse.json();
                    if (graphResult.code === 200 && graphResult.data) {
                        setGraphData(graphResult.data);
                        setAnalysisPhase('complete');
                    }
                } else {
                    // 同一攻击：增量合并
                    console.log('[自动轮询] 同一攻击，准备增量合并');
                    
                    const graphResponse = await fetch('http://127.0.0.1:8985/api/tracing/result/generate-graph', {
                        method: 'POST',
                        headers: { 'Content-Type': 'application/json' },
                        body: JSON.stringify({
                            source_ip: latestAlert.sourceIp,
                            target_ip: latestAlert.targetIp,
                            attack_type: latestAlert.attackType
                        })
                    });
                    
                    const graphResult = await graphResponse.json();
                    if (graphResult.code === 200 && graphResult.data) {
                        // 使用增量合并
                        mergeGraphData(graphResult.data, incomingThreatId);
                    }
                }
            }
        } catch (error) {
            console.error('[自动轮询] 轮询失败:', error);
        }
    }, 2000); // 每 2 秒轮询一次

    // 清理定时器
    return () => {
        console.log('[自动轮询] 停止轮询');
        clearInterval(pollInterval);
    };
}, [viewMode, pidsStarted, currentThreatId, mergeGraphData]);
```

## 🚨 常见问题

### Q1: 控制台没有看到 `[自动轮询]` 日志？

**可能原因：**
1. PIDS 分析未启动
2. 不在 PIDS 视图

**解决方法：**
1. 点击任意告警记录
2. 点击"启动 PIDS 分析"按钮
3. 确认在"增强版分析视图"页面

### Q2: 轮询日志显示但图谱不更新？

**可能原因：**
1. 后端 API 返回错误
2. 数据库中没有新记录

**解决方法：**
1. 检查控制台是否有错误日志
2. 检查数据库是否有新记录
3. 检查 Java 后端日志

### Q3: 图谱每次都清空，没有增量合并？

**可能原因：**
1. Python NIDS 每次生成了不同的 `threatId`
2. 前端 `currentThreatId` 状态异常

**解决方法：**
1. 检查 Python NIDS 日志，确认 `threatId` 是否相同
2. 检查控制台日志，查看 `currentThreatId` 的值

### Q4: 轮询频率太高，服务器压力大？

**解决方法：**
修改轮询间隔（默认 2000ms）：

## 📈 性能优化

### 1. 调整轮询频率

根据实际需求调整轮询间隔：
- **实时性要求高**：1000ms（1 秒）
- **平衡性能和实时性**：2000ms（2 秒，默认）
