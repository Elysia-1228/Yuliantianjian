# 增量合并图谱 (Incremental Graph Merge) 测试指南

## 📋 功能概述

本次升级实现了**增量合并图谱**功能，前端能够根据 `threatId` 智能判断是新攻击还是同一攻击的追加节点，实现节点的"生长"动画效果。

## 🎯 核心机制

### Python NIDS (流式上报)

```python
# 基于 IP 生成固定的 UUID
SHARED_THREAT_ID = str(uuid.uuid5(uuid.NAMESPACE_DNS, src_ip))

# 同一个攻击源的所有行为，都会使用相同的 threatId
# 分多次推送不同的节点数据
for item in chain_events:
    alert_data = {
        "threatId": SHARED_THREAT_ID,  # 🔑 关键：永远锁定
        "affectedProcess": item['proc'],
        "affectedFile": item['file']
    }
    requests.post(ALERT_API_URL, json=alert_data)
```

### 前端 React (增量合并)

```typescript
// 1. 判断是新攻击还是增量更新
const isNewAttack = currentThreatId !== incomingThreatId;

if (isNewAttack) {
    // 新攻击：清空旧图谱
    setGraphData(null);
    setCurrentThreatId(incomingThreatId);
} else {
    // 同一攻击：增量合并节点
    mergeGraphData(data, incomingThreatId);
}

// 2. 增量合并算法
const mergeGraphData = (newData, threatId) => {
    setGraphData((prevData) => {
        // 合并节点（去重）
        const existingNodeIds = new Set(prevData.nodes.map(n => n.id));
        const newNodes = newData.nodes.filter(n => !existingNodeIds.has(n.id));
        const mergedNodes = [...prevData.nodes, ...newNodes];
        
        // 合并边（去重）
        const existingEdgeKeys = new Set(
            prevData.edges.map(e => `${e.source}-${e.target}`)
        );
        const newEdges = newData.edges.filter(
            e => !existingEdgeKeys.has(`${e.source}-${e.target}`)
        );
        const mergedEdges = [...prevData.edges, ...newEdges];
        
        return { nodes: mergedNodes, edges: mergedEdges };
    });
};
```

### 场景 1：单次攻击（验证基础功能）

2. 选择 "1. SQL 注入"

- 控制台日志：`[增量合并] 初始化图谱，节点数: 4`

### 场景 2：连续攻击（验证增量合并）

**操作步骤：**
1. 在攻击机上运行 `python3 attack.py`
2. 选择 "1. SQL 注入"
3. **连续执行 3 次**（不要关闭程序）

**预期效果：**
- **第一次**：图谱显示 4 个节点
- **第二次**：图谱**不清空**，追加新节点，总共显示 8 个节点
- **第三次**：图谱**不清空**，追加新节点，总共显示 12 个节点
- 控制台日志：
  ```

    原有节点: 4
    新增节点: 4
    合并后节点: 8
  ```

### 场景 3：切换攻击类型（验证清空逻辑）

**操作步骤：**
1. 先执行 "1. SQL 注入"
2. 等待图谱显示完成
3. 再执行 "2. Webshell"

**预期效果：**
- **SQL 注入**：显示 4 个节点（nginx → php-fpm → mysqld → users.ibd）
- **切换到 Webshell**：图谱**清空**，显示新的 4 个节点（apache2 → php-cgi → bash → shell.php）
- 控制台日志：
  ```

    旧 threatId: abc123...
    新 threatId: def456...
  ```

### 场景 4：不同 IP 攻击（验证 threatId 隔离）

**操作步骤：**
1. 修改 `attack.py` 中的 `TARGET_LINUX_IP` 为 `10.138.50.151`
2. 执行 SQL 注入攻击
3. 修改 `TARGET_LINUX_IP` 为 `10.138.50.152`
4. 再次执行 SQL 注入攻击

**预期效果：**
- **第一次**（10.138.50.151）：显示 4 个节点
- **第二次**（10.138.50.152）：图谱**清空**，显示新的 4 个节点
- 原因：不同的 `src_ip` 会生成不同的 `threatId`

## 🚨 常见问题

### Q1: 图谱每次都清空，没有增量合并效果？

**可能原因：**
1. 前端没有正确接收到 `threatId`
2. Python NIDS 每次生成了不同的 `threatId`

**解决方法：**
```bash
# 1. 检查 Python NIDS 日志
tail -f /opt/pids/nids.log | grep "ID锁定"

# 应该看到相同的 ID
✅ [增量上报] 节点已追加: nginx (ID锁定: 12345678)
✅ [增量上报] 节点已追加: php-fpm (ID锁定: 12345678)  # 相同！

# 2. 检查前端控制台
# 应该看到：
[PIDS] 同一攻击，准备增量合并节点
  threatId: 12345678-1234-5678-1234-567812345678
```

### Q2: 节点重复出现？

**可能原因：** 去重逻辑失效。

**解决方法：**
检查前端控制台，应该看到：
```
[增量合并] 同一攻击，追加新节点
  原有节点: 4
  新增节点: 0  # 如果是 0，说明去重成功
  合并后节点: 4
```

### Q3: 图谱显示混乱，节点重叠？

**可能原因：** 节点布局算法需要优化。

**解决方法：** 前端的 `TopologyGraph` 组件会自动计算节点位置，如果节点过多，可能需要调整布局算法。

## 📈 性能优化

### 1. 限制节点数量

如果攻击持续时间很长，节点数量可能会爆炸。建议在前端添加节点数量限制：

```typescript
const MAX_NODES = 50;

const mergeGraphData = (newData, threatId) => {
    setGraphData((prevData) => {
        // ... 合并逻辑 ...
        
        // 限制节点数量
        if (mergedNodes.length > MAX_NODES) {
            console.warn('[增量合并] 节点数量超限，保留最新的 50 个');
            return {
                nodes: mergedNodes.slice(-MAX_NODES),
                edges: mergedEdges
            };
        }
        
        return { nodes: mergedNodes, edges: mergedEdges };
    });
};
```

### 2. 添加时间窗口

如果同一攻击源的攻击间隔超过 5 分钟，可以认为是新的攻击：

```python
# Python NIDS
ATTACK_TIME_WINDOW = 300  # 5 分钟

last_attack_time = {}

def push_alert(attack_type, src_ip, dst_ip):
    now = time.time()
    
    # 检查时间窗口
    if src_ip in last_attack_time:
        if now - last_attack_time[src_ip] > ATTACK_TIME_WINDOW:
            # 超过 5 分钟，生成新的 threatId
            threat_id = str(uuid.uuid4())
        else:
            # 5 分钟内，使用固定的 threatId
            threat_id = str(uuid.uuid5(uuid.NAMESPACE_DNS, src_ip))
    else:
        threat_id = str(uuid.uuid5(uuid.NAMESPACE_DNS, src_ip))
    
    last_attack_time[src_ip] = now
```
