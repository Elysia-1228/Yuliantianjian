## 三、逐步检查与调整

### 步骤 1：检查 BackCode 的区块链配置

打开文件：`BackCode/src/main/resources/application.yml`

确认最后几行是否存在（应该已经有了）：
```yaml
external:
  blockchain-gateway:
    url: ${BLOCKCHAIN_GATEWAY_URL:http://localhost:8986/api/chain/alert}
```

**说明**：BackCode 在以下两个地方会自动调用区块链网关：
1. **NIDS告警上链**：`AnalysisServiceImpl.saveAlert()` → 保存告警后自动 POST 到区块链
2. **溯源结果上链**：`TracingServiceImpl.saveTracing()` → 保存溯源记录后自动 POST 到区块链

如果你不想启用区块链（单机测试），可以把 URL 改成不存在的地址，代码内部有 `try-catch` 不会报错：
```yaml
external:
  blockchain-gateway:
    url: http://localhost:9999/disabled  # 禁用区块链（测试用）
```

---

### 步骤 2：确认区块链接口已对接

queue友的区块链网关（`backend/`）对外暴露以下接口，`BackCode` 需要调用的只有一个：

| 接口 | 方法 | 路径 | BackCode调用位置 |
|------|------|------|-----------------|
| **告警上链** | POST | `http://localhost:8986/api/chain/alert` | `AnalysisServiceImpl.saveAlert()` |
| 溯源上链 | POST | `http://localhost:8986/api/chain/trace` | `TracingServiceImpl.saveTracing()` |

区块链网关需要请求头 `X-API-KEY: secret-api-key`。检查 `BackCode` 的 RestTemplate 配置是否有添加此头（如果没有，需要补充）。

**检查方法**：搜索 BackCode 中是否有设置 `X-API-KEY`：
```
在 BackCode/src/ 目录中全局搜索 "X-API-KEY"
```

如果没有，在 `BackCode` 的 RestTemplate Bean 配置里添加：
```java
// 在 RestTemplateConfig.java 或 AppConfig.java 中
@Bean
public RestTemplate restTemplate() {
    return new RestTemplateBuilder()
        .defaultHeader("X-API-KEY", "secret-api-key")
        .build();
}
```

## 四、完整启动顺序（验证集成效果）

按照以下顺序启动各组件，验证整个系统是否正常运行：

### 前提条件
- MySQL 8.0 已启动，数据库 `net_safe` 存在
- JDK 17（BackCode）和 JDK 8+/11+（blockchain）已安装
- Python 3.x、torch、fastapi、uvicorn、scapy 等已安装
- （如需区块链）WSL2 + Docker + Hyperledger Fabric 网络已在 WSL 中启动

### 启动顺序

```
第1步：启动 MySQL（确认 net_safe 数据库已创建）

第2步：启动 BackCode（Java主后端，端口8985）
  方式：在 BackCode/ 目录运行 mvn spring-boot:run
  或：用 IntelliJ IDEA 直接运行 BackcodeApplication.java
  成功标志：控制台显示 "Started BackcodeApplication on port 8985"

第3步：启动区块链网关（可选，端口8986）
  ⚠️ 需要在 WSL2 内的 Linux 环境中启动，不能在 Windows 中直接运行
  方式：在 WSL 中进入 backend/ 目录，运行 mvn spring-boot:run
  成功标志：控制台显示启动成功，端口8086（或8080，根据backend/application.yml配置）

  注意：如果区块链暂不可用，在 application.yml 中将区块链URL设为无效地址即可
  BackCode 的 saveAlert() 方法内有 try-catch，区块链挂了不影响其他功能

第4步：启动 PIDS FastAPI（端口7890）
  方式：在 PythonIDS/ 目录运行：
    python -m PIDS.pids_feature_api
  成功标志：控制台显示 "Uvicorn running on http://0.0.0.0:7890"

第5步：启动 FrontCode 前端（端口5173）
  方式：在 FrontCode/ 目录运行：
    npm install（首次需要）
    npm run dev
  成功标志：浏览器打开 http://localhost:5173 可以看到登录页

第6步（可选，需要root/管理员权限）：启动 NIDS
  方式：管理员权限运行：
    python PythonIDS/NIDS/realtime_detection.py
  成功标志：控制台显示 "开始监听网络接口..."

第7步（可选）：运行攻击模拟
  方式：新开终端运行：
    python PythonIDS/NIDS/attack_scripts/quick_attack.py
  成功标志：前端告警页面出现实时告警数据
```

## 六、常见问题排查

### Q1：NIDS 启动报错 "No module named scapy"
```bash
pip install scapy torch numpy requests
```

### Q2：PIDS 启动报错 "No module named fastapi"
```bash
pip install fastapi uvicorn pydantic numpy scikit-learn
```

### Q3：BackCode 启动报错数据库连接失败
检查 `BackCode/application-dev.yml`，确认 MySQL 地址、用户名、密码正确。

### Q4：前端报 "Network Error"
检查 BackCode（8985）是否已正常启动；前端使用 Vite 代理转发 `/api/*` 到 `localhost:8985`。

### Q5：溯源图谱是空白/无节点
原因：`potential_threat_alert` 表中没有 `affectedProcess` 字段数据。
解决：先运行攻击模拟产生告警，这些告警会携带 `affectedProcess` 数据，然后再生成溯源图谱。

### Q6：区块链上链失败（但其他功能正常）
这是正常的，区块链需要在 WSL2 中运行 Hyperledger Fabric 网络，环境搭建比较复杂。
其他功能（NIDS/PIDS/前端展示）不依赖区块链，可以独立运行。
